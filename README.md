## Experiment orchestration toolkit

Everything below this line is a real, working toolkit for running
parameterized experiment sweeps and collecting their results — the
operational tooling around an experiment, not the experiment itself.

### Layout

```
bin/
  sweep          # orchestrator: expand a grid, run N combos concurrently, resume
  sweep-worker   # runs one combination, captures stdout/stderr/exit/wall-time
  capture-env    # snapshots interpreter, packages, git state, OS/arch
  aggregate      # reads results.jsonl, ranks by metric, exports CSV
lib/
  grid_expand.py   # expands a params grid (JSON or YAML) into combinations + stable hash
  lock.sh          # portable mkdir-based mutex (no flock(1) on macOS)
  append_jsonl.sh  # locked, interleave-safe JSONL append
examples/
  grid.json / grid.yaml   # example parameter grids
  toy_experiment.py       # toy command that prints {"metric": ...} from its params
tests/
  *.bats           # bats test suite (run with `bats tests/*.bats`)
```

### Quick start

```sh
# Run a 4x3 grid (12 combinations) with 4 concurrent workers:
bin/sweep --config examples/grid.json --results /tmp/my-sweep --jobs 4 \
  -- python3 examples/toy_experiment.py

# Summarize, best (lowest) metric first, export CSV:
bin/aggregate --results /tmp/my-sweep --metric metric --order asc --csv /tmp/my-sweep/summary.csv

# Capture the environment alongside the results for reproducibility:
bin/capture-env . > /tmp/my-sweep/manifest.json

# If a sweep was interrupted, resume without rerunning completed combos:
bin/sweep --config examples/grid.json --results /tmp/my-sweep --jobs 4 --resume \
  -- python3 examples/toy_experiment.py
```

### How it works

- **Grid expansion** (`lib/grid_expand.py`): takes a config with a `params`
  object mapping each parameter name to a list of values, and emits one
  JSON line per combination (the Cartesian product), each carrying a
  `param_hash` — a sha256 of the params sorted by key — used as the
  resume/dedupe key.
- **Concurrency** (`bin/sweep`): bounded with a classic named-pipe
  token-bucket semaphore. A FIFO is pre-loaded with `--jobs` tokens; each
  worker consumes one before starting and returns it on completion, so at
  most `--jobs` workers ever run at once no matter how many combinations
  exist. Verified in `tests/sweep.bats` by measuring real peak concurrency
  with marker files, not just checking the exit code.
- **Per-run capture** (`bin/sweep-worker`): sets each param as a
  `PARAM_<NAME>` environment variable (plus `PARAMS_JSON` and
  `PARAM_HASH`), runs the user command, and appends one JSONL record with
  exit code, wall-clock time, and stdout/stderr log paths. Concurrent
  writers to the shared `results.jsonl` are serialized through
  `lib/lock.sh`, a portable `mkdir`-based mutex (macOS ships without
  `flock(1)`).
- **Resume** (`bin/sweep --resume`): reads `results.jsonl`, collects the
  `param_hash` of every run with `status == "completed"`, and skips those
  combinations on the next invocation — only unrun or previously failed
  combinations are relaunched.
- **Aggregation** (`bin/aggregate`): pulls a named metric out of each run's
  captured stdout (expects a JSON object printed by the experiment
  command, e.g. `{"metric": 0.42}`), ranks runs by that metric (failed or
  metric-less runs sort last), supports `--top N` and `--order asc|desc`,
  and can export the ranked table as CSV with `--csv`.

### Running the tests

```sh
brew install shellcheck bats-core   # if not already installed
shellcheck -x bin/* lib/*.sh tests/helpers.bash
bats tests/*.bats
```

The suite exercises grid expansion, the mutex under real concurrent
contention, environment capture against clean/dirty git worktrees, single-run
capture in `sweep-worker`, concurrency bounding and resume behavior in the
`sweep` orchestrator (including an end-to-end run of the toy experiment), and
result aggregation/CSV export.
